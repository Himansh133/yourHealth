# Clean test set (v2): final numbers

Dataset v2 was generated with a new seed (2) after all development on v1 was finished: 30 new patients, 146 new
reports (layouts, values, dates and photo damage all new), 57 test questions. Every system was run once on its test
split with the final settings (DeepSeek-V4-Flash, thinking off for all). Nothing was changed after seeing these numbers.

Tables: `2026-10-30-v2_rag_test.md` (B0 / B1 / Ours), `2026-10-30-v2_ablations_test.md`,
`2026-10-30-v2_extraction_test.md`. The v1 tables are kept for comparison.

## Headline (Ours vs plain LLM B0 vs vector RAG B1)

- Value accuracy: 100% English and Hindi; B0 78% / 67%, B1 78% / 56%.
- Medicine (names the right generic): 100% vs 0% / 0%: the baselines only see report text.
- Treatment safety: 100% vs 25% / 25%.
- Wrong abstentions on answerable questions: 0% vs 20% / 20%.
- Made-up numbers: 0% vs 3% / 6%.
- Injection: no system followed the planted instruction.
- Latency: median 3.3 s, p95 8.2 s (v1 with thinking on: 6.3 s / 34.2 s). Baselines are faster (2.4 s / ~3 s):
  one LLM call, no router or validation.

## Ablations

- Without the router: medicine 100% → 0%, safety 100% → 38%, made-up numbers 0% → 15%, value accuracy 100% → 89%,
  wrong abstentions 0% → 10%, 18% of answers fall back to the facts table. Same result as on v1.
- Without the reranker or the validator: no meaningful change (one trend question differs, judged by an LLM).
  Same as on v1; see problem 8.16.

## Extraction on new reports

F1 95.1% (v1 test 98.1%), value accuracy 100%. PDFs 100%; clean photos 82.9%, degraded photos 89.7%. All 13
mistakes are rows lost from photos (mostly enzyme rows in the range-first layout), none is a wrong value. The drop
is the generalisation gap the v1 number hid; it is reported as is, not tuned away.
